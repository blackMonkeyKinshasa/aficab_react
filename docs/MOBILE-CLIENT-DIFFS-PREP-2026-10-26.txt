2. FACTURATION — PRIORITÉ P1 CLIENT
--------------------------------------------------------------------------------

2.1 État Expo
  Fichiers concernés aujourd’hui : aucun helper invoice dans api/booking.ts
  Onglets : (tabs)/reservation.tsx, settings — pas d’entrée « Facturation »
  BookingDetailModal : paie / annule / review — pas de téléchargement document

2.2 Ce que le backend offre DÉJÀ (web livré)
  GET /api/booking/{id}/invoice
    Auth : client propriétaire | ORG_BOOKER | admin
    Refus : status CANCELED uniquement
    Réponse :
      - proforma: true  → id PRO-{bookingId} si non payé / non ENDED|ARCHIVED
      - proforma: false → id FAC-{bookingId} si isPaid || ENDED || ARCHIVED
      - total, issuedAt, dueAt, paidAt, client, vehicle, service…

2.3 Ce qu’il manque encore côté backend pour Expo
  GET /api/booking/{id}/invoice.pdf
    Même auth / mêmes règles proforma vs facture
    Content-Type: application/pdf
    Content-Disposition: attachment; filename="PRO-….pdf" | "FAC-….pdf"
  Raison : invoice-pdf.ts web utilise fetch logo + canvas (navigateur).
  Expo ne peut pas réutiliser ce module tel quel → PDF serveur obligatoire.

7. CONTRATS API À RESPECTER (RÉFÉRENCE RAPIDE)
--------------------------------------------------------------------------------

GET  /api/booking/{id}/invoice
  200 { id, bookingId, proforma, issuedAt, dueAt, paidAt, total, … }
  403 FORBIDDEN | 404 BOOKING_NOT_FOUND | 409 INVOICE_NOT_AVAILABLE (canceled)

GET  /api/booking/{id}/invoice.pdf   ← À AJOUTER
  200 application/pdf
  mêmes 403/404/409

POST /api/booking
  options.dayExtensions?: [{ day: "YYYY-MM-DD", type: "Flex"|"Premium" }]
  options fuel / priceOptions côté catalogue voiture

POST /api/booking/{id}/client-update
POST /api/booking/{id}/client-cancel
